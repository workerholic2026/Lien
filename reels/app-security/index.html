AI로 만든 내 앱, 해커가 먼저 해 보는 3가지 🔐 요즘은 코딩을 몰라도 클로드 코드, 커서 같은 AI 도구로 앱을 뚝딱 만들어요. 그런데 AI는 「돌아가는 앱」을 만들어 줄 뿐, 시키지 않으면 「뚫리지 않는 앱」까지 꼼꼼히 챙겨 주지는 않아요. 그래서 만든 사람이 꼭 한 번은 점검해야 해요. 📌 세계 웹 보안 단체가 꼽은 위험 1위 웹 보안 단체 OWASP(오와스프)는 몇 년마다 웹 서비스의 가장 큰 위험 10가지를 발표해요. 2025년 목록에서도 1위는 「권한 확인 실패」였어요. 2021년에 이어 다시 1위예요. 쉽게 말해 「이 정보의 주인이 지금 들어온 사람이 맞는지」 서버가 확인하지 않는 문제예요. 📌 첫째, 주소 숫자 바꾸기 내 주문 주소 끝의 숫자 하나만 바꿨는데 남의 이름·연락처·주소가 보이는 경우가 있어요. 화면에서 버튼을 숨겨도 소용없어요. 해커는 화면을 거치지 않고 주소로 바로 요청을 보내니까요. 주문·회원 정보를 보여 주는 곳마다 「주인이 맞는지」 서버가 확인해야 해요. 📌 둘째, 주소창에 /admin 쳐 보기 관리자 메뉴만 숨기고 관리자 화면 자체는 로그인 확인 없이 열리게 만든 경우예요. 회원 목록 내려받기, 가격 고치기, 쿠폰 만들기 같은 기능이 그대로 열려요. 메뉴를 숨기는 건 막은 게 아니에요. 📌 셋째, 화면 코드에 넣어 둔 비밀 키 AI 도구나 결제 서비스의 비밀 키를 화면으로 보내는 코드에 넣으면 누구나 꺼내 볼 수 있어요. 예를 들어 넥스트JS(Next.js) 공식 안내에는 이름이 NEXT_PUBLIC_ 으로 시작하는 값은 사용자의 브라우저로 보내는 코드에 그대로 들어간다고 적혀 있어요. 키가 새면 남이 내 카드로 AI를 쓰게 돼요. 📌 깃허브에 이미 올린 키는 결국 새로 발급 코드에서 키를 지워도 저장 기록에는 남아 있어요. 깃허브 공식 안내도 비밀번호나 키가 올라갔다면 가장 먼저 그 키를 폐기하고 새로 발급하라고 해요. 기록 지우기는 그다음 일이에요. 📌 랜딩 페이지 하나만 만들었어도 로그인이나 결제가 없어도 비밀 키를 쓰는 곳이 있다면 셋째(비밀 키)와 깃허브 키 확인은 꼭 하세요. 영상 속 가게 화면은 설명을 위해 만든 예시이고, 실제 가게가 아니에요. 💬 해커가 해 보는 14가지 점검표와, AI에게 내 코드를 점검시키는 요청문을 정리했어요. 댓글에 「보안」이라고 남겨 주시면 DM으로 보내 드릴게요. 출처: OWASP Top 10:2025 A01 권한 확인 실패 · 넥스트JS 공식 문서 「환경 변수」 · 깃허브 공식 문서 「저장소에서 민감한 정보 지우기」 · 참고: lune-seo2 바이브코딩 보안 점검 안내 #바이브코딩 #앱보안 #클로드코드 #AI코딩 #AI소식
