홈페이지 용어 7개, AI에게 이렇게 말하세요용어마다 뜻 한 줄 + 그대로 복사해 쓰는 요청문
AI에게 홈페이지를 만들어 달라고 할 때, 화면 부분의 이름을 알면 결과가 확 달라져요 🧱 「위에 메뉴 같은 거 넣어줘」보다 「헤더를 만들어줘」가 훨씬 정확하게 나와요. 바이브 코딩(AI에게 말로 시켜 만드는 것) 용어를 정리한 글 12곳을 비교해서, 가장 많이 나오고 모르면 시키기 어려운 7개를 골랐어요. 📌 1. 헤더 홈페이지 맨 위 띠. 로고·메뉴·로그인 버튼이 들어가는 자리예요. (12곳 중 6곳) 예) 「맨 위에 헤더를 만들어줘. 왼쪽에 로고, 오른쪽에 메뉴 4개.」 📌 2. 푸터 맨 아래 띠. 연락처·저작권·약관 링크를 두는 곳이에요. (8곳) 예) 「맨 아래 푸터에 상호명, 이메일, 인스타 링크를 한 줄로.」 📌 3. 히어로 섹션 열자마자 보이는 큰 첫 화면. 큰 제목 + 설명 + 버튼 하나. (7곳) 예) 「히어로 섹션에 큰 제목, 설명 한 줄, 「무료로 시작하기」 버튼 하나.」 📌 4. 팝업(모달) 화면 위에 떠서 뒤를 막는 창이에요. 웹 표준 문서(MDN)는 뒤 화면을 못 누르게 막는 창을 「모달」, 막지 않는 창을 「팝오버」로 나눠요. AI에게는 뒤를 막는지 같이 말해 주면 정확해요. 📌 5. 카드 사진·제목·설명·버튼을 네모 상자 하나에 묶은 것. 상품·후기 목록에 써요. (7곳) 예) 「상품을 카드로, 한 줄에 3개씩.」 📌 6. 고정(스티키) 스크롤을 내려도 메뉴가 화면 위에 따라붙는 것이에요. 「헤더를 고정해줘」 한마디면 돼요. 📌 7. 반응형 폰·태블릿·컴퓨터 화면 크기에 맞춰 모양이 저절로 바뀌는 것. 「모바일에서는 메뉴를 줄 세 개 버튼으로 접어줘」처럼 화면별로 말해 주세요. 📌 잘 시키는 공식 「어디에」 + 「무엇을」 + 「몇 개·어떤 모양」을 함께 말하세요. 막연하게 「메뉴 만들어줘」라고 하면 결과도 막연하게 나와요. 💬 댓글에 「자료」라고 남겨 주시면 용어별로 AI에게 그대로 붙여 넣을 요청문 7개를 DM으로 보내 드려요 출처 ・MDN 웹 문서 (header·footer·dialog·position·반응형 디자인 정의) ・위키독스 「바이브코딩 실전 용어 가이드」, 셰코즈 「UI Elements」 등 바이브 코딩 용어 정리 글 12곳 비교 #바이브코딩 #AI활용 #홈페이지만들기 #웹디자인용어 #클로드
